Manual

Five jobs. Certificates live in Settings, and the KDM page uses that chain. The same commands are below for a terminal.

  1. Build a DCP
  2. Encrypt it
  3. Make a KDM
  4. Re-wrap a DKDM
  5. Export the recipient certificate

Build a DCP

Pick the master, set the title, and build. The package is a folder named after the title inside the output directory. Sound comes from the video. Add a separate WAV when the mix is its own file.

dcpwizard create --title "My Film" --video movie.mov --output ./dcp

Encrypt it

In Settings, Certificates, choose Create signing chain and pick a folder. That writes the leaf, the intermediate, the root, and their keys, and the app remembers the paths.

Tick Encrypt in Properties and choose a keys file that sits outside the package. The build signs with the whole chain. A finished clear package stays clear. The keys file is the plaintext content keys. Keep it.

dcpwizard certificate chain --organization "Studio" --output ~/dcp-certs
dcpwizard create --title "My Film" --video movie.mov --output ./dcp \
  --encrypt --key-out ~/keys/my-film.json \
  --signer-cert ~/dcp-certs/signer.pem \
  --signer-key ~/dcp-certs/signer.key \
  --signer-chain ~/dcp-certs/intermediate.pem \
  --signer-chain ~/dcp-certs/root.pem

Make a KDM

Open Encryption & KDM. Pick the encrypted DCP. The composition id and title fill in. Pick the screen's certificate, the keys file from the build, the dates, and where to write the KDM. The signature comes from Settings.

Tick DKDM for this machine when the recipient is you. That uses the recipient certificate from Settings, so you can reissue it later.

dcpwizard kdm \
  --cpl-id <cpl-uuid> \
  --content-title "My Film" \
  --cert screen.pem \
  --signer-cert ~/dcp-certs/signer.pem \
  --signer-key ~/dcp-certs/signer.key \
  --signer-chain ~/dcp-certs/intermediate.pem \
  --signer-chain ~/dcp-certs/root.pem \
  --keys ~/keys/my-film.json \
  --valid-from now --valid-to "2 weeks" \
  -o screen.kdm.xml

Re-wrap a DKDM

On the same page, From a DKDM takes the DKDM, the private key it was issued to, and the new screen certificate. Leave the dates empty to keep the DKDM's window. Tick Unwrap with this machine's key when the DKDM was made for you.

dcpwizard kdm-rewrap \
  --dkdm my.dkdm.xml \
  --dkdm-key ~/dcp-certs/recipient.key \
  --cert screen.pem \
  --signer-cert ~/dcp-certs/signer.pem \
  --signer-key ~/dcp-certs/signer.key \
  --signer-chain ~/dcp-certs/intermediate.pem \
  --signer-chain ~/dcp-certs/root.pem \
  -o screen.kdm.xml

Export the recipient certificate

This is the certificate other software uses to make a KDM for this machine. Create recipient certificate in Settings writes one, signed by the intermediate from the chain. If DCP-o-matic is already installed, Import from DCP-o-matic copies its decryption certificate and private key instead.

Export certificate writes a public copy. Send that file. The private key stays here, and the button will not write a file that also holds a key.

The QC tool uses the certificate to aim a KDM at this copy of DCP Wizard. To open one of your encrypted DCPs over there, give it a KDM aimed at the QC tool, or give it the keys file from the build.

dcpwizard preferences import-dcpomatic
